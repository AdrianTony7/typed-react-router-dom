# Changelog
---

## [0.3.0] - 2026-09-10

### Added
- **Automatic Path Parameter Extraction**:
  - Implemented `ExtractParamKeys<Path>` template-literal parser type that automatically extracts `:param` tokens from route paths (e.g. `'/users/:id/posts/:postId'` -> `'id' | 'postId'`).
  - `RouteParams<R>` now infers parameter shapes directly from `route.path` without needing manual `paramKeys`.
- **Runtime Path Parameter Extraction**:
  - Added `RouteHelper.extractParamKeysFromPath(path)` to extract `:param` tokens directly from route path strings at runtime.
  - `RouteHelper.constructHref`, `RouteHelper.isRouteMatchByUrl`, and `AppRouterService.navigateToRoute` now dynamically check parameter requirements directly against `route.path`.
- **`<TypedRoute />` & `<RouteComponent />`**:
  - Introduced `<TypedRoute />` to replace `react-router-dom`'s `<Route />` with type-safe `path` checking against defined routes.
  - Preserves exact runtime reference identity with React Router's `Route` component to satisfy `<Routes>` child validation.
  - Added `<RouteComponent />` as an alias for `<TypedRoute />`.
  - Added `router.TypedRoute` and `router.RouteComponent` to `createTypedRouter`.
- **`<TypedLink />` & `<Link />` Aliases**:
  - Primary component renamed from `<AppLink />` to `<TypedLink />` (along with `TypedLinkProps`).
  - Added `<Link />` as a drop-in type-safe alias for React Router's `<Link />`.
  - Added `router.Link` to `createTypedRouter`.

### Deprecated
- **`paramKeys`**:
  - Marked `@deprecated` on `Route` definition. Path parameters are now inferred automatically from `path`. Scheduled for removal in `v1.0.0`.
- **`queryKeys`**:
  - Marked `@deprecated` on `Route` definition. Use `queryType` for full compile-time type safety across unions, numbers, and booleans. Scheduled for removal in `v1.0.0`.
- **`<AppLink />` / `AppLinkProps`**:
  - Marked `@deprecated`. Use `<TypedLink />` or `<Link />` instead. Retained for backwards compatibility until `v1.0.0`.

## [0.2.0] - 2026-09-10

### Added
- **Compile-Time Typed Query Parameters**:
  - Extended `Route` interface with optional `queryType?: TQuery` and `queryKeys?: readonly string[]`.
  - Added `RouteQueryParams<R>` utility type to resolve query parameter types from route definitions.
  - Added `useTypedSearchParams<R>(route?)` hook returning `[query, setQuery, searchParams]` for typed query string reading and updates.
  - Added `RouteHelper.extractQueryParams(searchOrUrl)` for parsing query string key-value pairs.
  - Updated `RouteHelper.constructHref` to serialize typed query parameters into URL search strings using native `URLSearchParams` (omitting `undefined` and `null`).
  - Updated `RouteHelper.isRouteMatchByUrl` to strip query strings before matching pathname patterns.
  - Updated `useTypedNavigate`, `useTypedMatch`, `AppLink`, and `AppRouterService` to support typed query parameters.
  - Scoped query param helpers into `createTypedRouter`.

---

## [0.1.0] - Initial Release

### Added
- Initial release of `typed-react-router-dom`.
- Type-safe route definitions with `defineRoutes`.
- `<AppLink />` component with required parameter validation.
- `useTypedNavigate`, `useTypedParams`, and `useTypedMatch` hooks.
- `RouteHelper` utility class for path interpolation and route lookup.
- `AppRouterService` / `appRouter` singleton for programmatic navigation outside the React tree.
- `createTypedRouter` factory for scoped router configurations.
